# Grapheme clusters (mode 2027)

A program that sets mode 2027 (`CSI ? 2027 h`) gets each grapheme cluster
in one cell, two when it is wide; `CSI ? 2027 $ p` (DECRQM) answers
`CSI ? 2027 ; 1 $ y` when it is set, `; 2 $ y` when it isn't. The mode
is off by default: programs that don't know about clusters count columns
with `wcwidth`, and the terminal does too.

## What goes into one cell

Whatever Unicode's rules for extended grapheme clusters (UAX #29, rules
GB3 to GB999) keep together: a letter and its combining marks, spacing
marks (Devanagari ि), Indic conjuncts (क्ष: consonant, virama,
consonant: rule GB9c), Hangul syllables written in jamo (ᄀ ᅡ ᆨ),
Prepend characters with what follows, emoji ZWJ sequences (👨‍👩‍👧), emoji
with skin tones, keycaps (#️⃣), tag flags, and regional indicator pairs
(🇮🇹).

The rules are in `src/grapheme.h`; the properties they use (Grapheme
Cluster Break, Indic Conjunct Break, Extended_Pictographic, Emoji) in
`src/grapheme-properties.h`, generated by
`tools/update-grapheme-properties.py` from GraphemeBreakProperty.txt and
emoji-data.txt (Unicode 17.0) and the InCB values of
DerivedCoreProperties.txt (Unicode 16.0; run the script with 17.0's file
on the next update). `tests/graphemes.C` checks every rule; the rules
were also compared with an independent implementation (uniseg, Unicode
16.0) on 20000 random strings of the interesting characters, with no
difference.

## Widths

A cluster takes the width of its first character (`wcwidth`), except:

- VS16 (U+FE0F) after an emoji that has a text form (❤ U+2764, the
  digits of keycaps) makes it two cells, as does the second letter of a
  flag: when there is room on the line and nothing written after it;
  otherwise it stays one cell wide.
- characters of no width (marks, joiners) never get a cell of their own:
  when they don't continue the cluster before them, they are added to it
  anyway, as without the mode.

Characters that continue a cluster go into it even at the end of the
line, where the next character would wrap.

## Drawing

With `--enable-emoji-sequences` (HarfBuzz), clusters of several code
points are shaped by the first font that has all of them: emoji
sequences by a colour font, others (marks, conjuncts, jamo) by any font.
The font's own rules then place the marks and form the conjuncts. A
conjunct wider than its cell runs into the next one, as in other
terminals: the cell grid has no room for scripts whose clusters have
other widths. Without HarfBuzz, or without a font that has the whole
cluster, the parts are drawn on top of each other as before.

## For programs

Selection, copying and the perl API see the code points of each cluster
(perl extensions get composed characters as their own codes, which
`$term->special_decode` expands; they used to get "?").
